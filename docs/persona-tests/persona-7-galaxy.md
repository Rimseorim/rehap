# 페르소나 7: 38세 남 · 크로스핏 숙련(4년차), 갤럭시(412×915)

## 인물 배경
수평 프레스 볼륨 늘리다 팔꿈치 불편.

## 선택 과정
- 통증부위: 팔꿈치 — 수평 프레스(벤치프레스) 볼륨을 늘린 시점부터 불편함이 시작됐으므로 팔꿈치를 선택.
- 동작: 수평 프레스 — 실제로 볼륨을 늘리던 동작이 수평 프레스였으므로 그대로 선택.

## 진행 기록 (레이아웃 관찰 포함)
1. 로그인: "데모로 시작" 링크로 진입. 412px 폭에서 로그인 화면 정상 렌더링.
2. 대시보드(기록/재활/추이 탭): "재활" 탭 → "지금 시작하기"로 새 감별 시작. 캘린더·기록 카드 레이아웃 문제 없음.
3. 통증 부위 선택: 8개 부위 카드 세로 나열, 잘림·겹침 없음. "팔꿈치" 선택.
4. 동작 선택: 5개 동작(풀업/키핑/로우/수직 프레스/수평 프레스) 정상 표시. "수평 프레스" 선택.
5. 감별 질문 1 - "통증이 언제 느껴지나요?": "어느 정도 반복한 후"를 선택 (볼륨 증가로 인한 과부하 패턴이므로 즉시 통증이 아니라 반복 후 느껴지는 것이 맞다고 판단).
6. 감별 질문 2 - "팔꿈치 어느 쪽이 아픈가요?": "안쪽 뼈 돌출부 (굴곡근 쪽)" 선택 (벤치프레스에서 그립·손목 굴곡 부하로 내측 통증이 흔하다고 판단).
7. 직접 테스트 - "역 코젠(Reverse Cozen's) 검사 — 팔꿈치 안쪽": 벤치프레스 시 팔꿈치 안쪽 통증을 재현하는 테스트로, 선택한 동작·부위와 정확히 일치하는 문항이 나와 자연스러웠음. "저항 중 팔꿈치 안쪽이 찌릿하거나 아파요" 선택(양성). 레이아웃 문제 없음, 3단계 안내와 버튼 모두 화면 안에 잘 배치됨.
8. 원인 확정: "내측 상과염 (골퍼 엘보 — 팔꿈치 안쪽) · 과부하"로 판정. 위험 신호(부종/열감/뚝 소리) 체크리스트 표시됐으나 해당 사항 없어 "재활 루트 보기" 클릭. 레이아웃 문제 없음.
9. 재활 루트 - 기초재활 단계 진입: 준비운동 4종(폼롤러 릴리즈, 손목 원형 돌리기, 손목 굴곡근 편심성 운동, 밴드 풀 어파트) 카드 리스트, 각 카드 방법 펼침/접힘, "왜 이 운동인가" 링크 모두 정상. 하단 "다음" 버튼도 스크롤 시 정상 노출(단, 브라우저 캡처 창 높이가 915px보다 낮아 마지막 소량 스크롤이 필요했던 것은 테스트 환경 문제이며 앱 자체 문제 아님).
10. 진행 단계 1/4: "덤벨 벤치프레스 (중립 그립, 경부하)" 운동 카드, 방법·왜 이 운동인가·진급 기준 모두 카드 안에 깔끔히 정리. "이 단계 완료" 클릭.
11. 세션 피드백 질문 "오늘 재활이 어떻게 느껴졌나요?": "할 만했다" 선택 (숙련자이므로 경부하 운동을 무난하게 소화했다고 판단).
12. "1단계 완료!" 화면: 체크 아이콘, 안내 문구, 4단계 탭, "내일 다시 오기"/"지금 바로 테스트하기"/"이 단계 운동 다시 보기" 버튼 모두 화면 안에 깔끔히 배치. 레이아웃 문제 없음.

## 발견된 문제
- [심각도: 데이터] 원인 확정 화면의 설명 텍스트가 "**풀업·키핑**에서 팔꿈치 안쪽 뼈(내측 상과)가 아프면..."으로 적혀 있음 — 실제 선택 경로는 "수평 프레스"였는데 설명 문구는 풀업/키핑 동작을 언급하고 있어 동작명이 실제 선택과 불일치함. 화면 제목("수평 프레스 팔꿈치 · 과부하")과 카드 안 설명 텍스트의 동작명이 서로 다른 상태 — 내용 검수 시 확인 필요. (원인 확정 화면, "내측 상과염" 카드 본문)

레이아웃 관련 문제는 없음 — 갤럭시 S24 기준 412×915 뷰포트에서 모든 화면이 잘림, 버튼 밖 이탈, 텍스트 겹침, 가로 스크롤 없이 정상 렌더링됨.

## 최종 결과
- 도달한 화면/판정: 팔꿈치 · 수평 프레스 · 과부하 → 내측 상과염(골퍼 엘보) 판정, 재활 루트 기초재활 1단계 완료 화면까지 도달.
- 412×915 화면에서 전반적인 사용성 평가: 전 화면에서 레이아웃이 안정적이며 버튼·카드 크기, 여백이 화면 폭에 잘 맞아 실사용에 문제없어 보임.
- 아이폰(390×844) 결과와 비교했을 때 차이점: 레이아웃 자체는 차이 없음. 다만 이번 테스트에서 원인 확정 화면의 설명 텍스트에 실제 선택 동작(수평 프레스)과 다른 동작명(풀업·키핑)이 노출되는 데이터 불일치를 새로 발견함 — 이는 뷰포트 차이가 아니라 콘텐츠 데이터 이슈로 보임.
