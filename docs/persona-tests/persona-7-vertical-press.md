# 페르소나 7: 29세 남 · 수직 프레스

## 프로필
- IT숙련도: 숙련 / 증상설명정확도: 부정확 / 증상민감도: 둔감 / 병원권유수용도: 수용적 / 크로스핏경력: 초보
- 시나리오: 어깨 통증, 베이스라인(위험신호 없음) — 원래 계획은 고관절+수직프레스였으나 앱이 해당 조합을 지원하지 않아(고관절 선택 시 동작 옵션이 스쿼트·런지·데드리프트뿐이고 수직 프레스는 오직 어깨 부위에서만 존재) 어깨로 정정하여 재실행

## 진행 기록
1. 로그인 화면: "데모로 시작" 클릭 → 정상 진입, 기록(캘린더) 탭이 첫 화면. 재활 탭으로 이동.
2. 재활 탭: 기존 진행 중인 재활(스쿼트·무릎, 기초 재활 단계) 카드 노출. "지금 시작하기" 클릭.
3. **통증 부위 선택 화면(10%)**: "어디가 아픈가요?" — 무릎/허리/발목/어깨/고관절/손목/팔꿈치/흉근 8종. "어깨" 선택.
   - 참고: 테스트 초반, 이전 세션의 localStorage(`rehab_progress`)가 남아있는 상태에서 빠르게 연속 클릭했을 때 통증 부위 선택 화면을 건너뛰고 곧바로 동작 선택 화면(발목/흉근 등 이전 세션 값)으로 진입하는 현상을 관찰. 자동화 도구의 연속 클릭이 원인으로 추정되며, 단발 클릭으로 재시도했을 때는 정상적으로 통증 부위 선택 화면(painSiteId=null)부터 시작함. 앱 코드(`goToPainSite()` → `go('pain_site')`) 자체는 문제 없어 보이나, **브라우저를 껐다 켜지 않고 이전 미완료 세션이 남아있는 상태에서 "지금 시작하기"를 빠르게 여러 번 누르면 의도치 않게 이전 세션의 잔여 상태와 뒤섞여 다른 부위/동작으로 튈 가능성** 자체는 재현되었으므로 데이터 갭이 아닌 "상태 복원 로직"쪽 리스크로 참고 기록.
4. **동작 선택 화면(30%)**: "어깨" 배지 노출, 선택지 7개(스쿼트/데드리프트/풀업/키핑/로우/수직 프레스/수평 프레스). "수직 프레스" 선택.
5. **감별 질문 1(챕터1·30→40%)**: "어깨 통증이 느껴지나요? (오버헤드 프레스 중 찝히거나 쉬는 중에도 아픈 경우 포함)" — "네, 통증이 있어요" 선택 (둔감 페르소나이지만 통증 자체는 인지).
6. **감별 질문 2(40→51%)**: "통증이 언제 느껴지나요?" (운동 시작하자마자/어느 정도 반복한 후/쉬는 중에도) — 둔감·과부하 패턴에 맞춰 "어느 정도 반복한 후" 선택.
7. **직접 테스트(챕터2·51→82%)**: "능동 어깨 굴곡 검사" — 팔을 머리 위로 완전히 들 수 있는지 확인하는 3단계 안내 + 영상 링크 제공. 결과 선택지 2개 중 "올리는 중 통증이 있거나 귀 옆까지 안 올라가요" 선택.
8. **원인 확정(82%)**: 태그 "가동성 부족", 진단명 "광배근·흉추 경직 (어깨 굴곡 공간 부족)" 배정. 설명 문단에 "왜 이 원인인가"에 해당하는 임상적 근거(팔꿈치 구부러짐/허리 꺾임은 보상 패턴이라는 설명) 포함 — 원칙 2(이유를 붙인다) 충족.
   - 같은 화면에 위험 신호 안내 박스(관절 부어있음/열감/팔 저항 시 뚝 떨어짐) 노출 — 해당 없으므로 정상적으로 재활 루트로 진행. 병원 권유로 전환되지 않음 (베이스라인 시나리오 의도와 일치).
   - **"기록 저장에 실패했습니다." 토스트 메시지 노출.** 로컬 테스트 환경이 정적 파일 서버(`python -m http.server`)만 띄운 상태라 백엔드(Railway API)가 연결되지 않아 발생한 것으로 추정 — 실제 배포 환경(Railway 연결)에서 재현되는지는 별도 확인 필요.
9. **재활 루트(82%)**: "수직 프레스 어깨 · 가동성 부족" 제목, 4단계 탭(1 기초재활/2 회복테스트/3 재평가/4 운동복귀) 노출, 현재 "기초 재활 진행 단계 1/4". 첫 운동 "네발기기 흉추 회전" 카드에 세트/방법 3단계/주의사항/영상 링크/"왜 이 운동인가" 토글 모두 정상 노출. 토글 클릭 시 "요추 고정 순수 흉추 회전을 훈련합니다. 오버헤드 프레스에서 흉추 신전과 회전 가동성이 모두 필요합니다." 설명 정상 표시.

## 발견된 문제
- [심각도: 데이터] **고관절/사타구니 + 수직 프레스 조합이 앱 데이터에 없음.** 통증 부위 "고관절" 선택 시 동작 옵션은 스쿼트·런지·데드리프트뿐이며, 수직 프레스는 오직 "어깨" 부위에서만 선택 가능함. 임상적으로 납득 가능하지만 원래 배정된 테스트 시나리오(고관절+수직프레스) 자체가 앱 구조상 실행 불가능했던 원인. (이전 시도에서 발견, 본 재실행에서도 재확인)
- [심각도: 사용성/데이터] **"기록 저장에 실패했습니다." 오류 토스트.** 원인 확정 화면 도달 시 노출됨. 로컬 정적 서버 환경(백엔드 미연결)에서 발생한 것으로 보이나, 사용자에게 실패 이유나 재시도 안내 없이 문구만 떠서 실제 배포 환경에서도 발생 시 감별 기록이 유실될 수 있음 — 원인 규명 필요.
- [심각도: 사용성] **연속 빠른 클릭 시 이전 세션 잔여 상태(localStorage)와 뒤섞이는 현상 관찰.** "지금 시작하기"를 매우 빠르게 여러 번 누르면 통증 부위 선택 화면을 건너뛰고 이전 세션에서 골랐던 부위/동작으로 바로 진입하는 사례가 있었음. 정상 속도의 단일 클릭에서는 재현되지 않았으나, 실사용자가 빠르게 두 번 탭하는 경우(예: 반응 없어 보여 재탭) 의도치 않은 부위로 진입할 잠재 리스크가 있어 참고 기록.

## 최종 결과
- 배정된 cause/루트: **가동성 부족 — 광배근·흉추 경직 (어깨 굴곡 공간 부족)** → 재활 루트 "수직 프레스 어깨 · 가동성 부족", 기초 재활 1/4 단계부터 시작.
- 시나리오 의도와 일치 여부: **일치.** 위험 신호에 해당하지 않는 답변(어느 정도 반복 후 통증, ROM 제한형 테스트 결과)을 선택했고 danger 경로로 전환되지 않은 채 정상적으로 원인 판정 → 재활 루트까지 완주함. "부정확한 증상설명" 페르소나 특성은 질문 선택지가 이미 큰 범주(운동 시작하자마자/반복 후/쉬는 중)로 단순화되어 있어 판정 정확도에 뚜렷한 악영향은 주지 않는 것으로 관찰됨 — 다만 선택지 자체가 넓어서 실제로는 다른 원인(예: 순수 과부하형)에 해당하는 사용자도 "가동성 부족" 계열로 쏠릴 여지는 있어 보임(추가 검증 필요).
