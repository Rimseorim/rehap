# 페르소나 6: 22세 여 · 크로스핏 초보(2개월차), 아이폰(390×844)

## 인물 배경
크로스핏 시작한 지 2개월차. 런지 동작을 배우던 중 무릎 앞쪽에서 뻐근하고 눌리는 듯한 이상한 느낌을 받음. 초보라 정확한 원인은 모르고 "뭔가 이상하다"는 감각만 있음.

## 선택 과정
- 통증부위: **무릎** — 런지 중 느낀 느낌이 무릎 쪽이었으므로.
- 동작: **런지** — 실제로 통증을 느낀 동작 그대로 선택.

## 진행 기록 (레이아웃 관찰 포함)
1. 로그인 화면: "데모로 시작" 클릭 → 기록 홈 진입. 레이아웃 문제 없음.
2. 재활 탭 → "지금 시작하기" 클릭 → 통증부위 선택 화면 진입. 8개 선택지(무릎/허리/발목/어깨/고관절/손목/팔꿈치/흉근) 모두 카드 형태로 세로 배치, 잘림 없음.
3. "무릎" 선택 → 동작 선택 화면(스쿼트/런지/데드리프트). "런지" 선택.
4. "통증이 언제 느껴지나요?" 질문 → 초보가 반복하면서 느낀 느낌이라 판단해 "어느 정도 반복한 후" 선택.
5. "무릎 어느 쪽이 아픈가요?" 질문 → 런지에서 흔한 슬개골 전방부 통증으로 판단해 "앞쪽 (슬개골 주변)" 선택.
6. 챕터2 "발목 배측굴곡 테스트" 화면 진입 → 직접 테스트 안내(1·2·3 스텝, 영상 보기 버튼) 표시. 초보이고 가동성이 부족할 가능성이 높다고 판단해 "뒤꿈치가 들리거나 닿지 않아요" 선택.
   - 이 화면에서 390px 폭 iframe 미니뷰포트로 확인: 안내 텍스트 3줄 모두 자연스럽게 줄바꿈, "영상으로 보기" 버튼 폭 꽉 차지만 잘리지 않음. 레이아웃 문제 없음.
7. danger 화면(관절 부종/열감 경고 문구)이 원인 확정 화면 안에 함께 표시됐으나, 두 경고 항목 모두 해당 없다고 판단(붓기·열감 없음)하고 "재활 루트 보기"로 진행 — danger 전용 화면으로 전환되지는 않음(경고 문구는 참고용 안내로만 노출).
8. "원인을 찾았습니다" 화면: 태그 "가동성 부족", 진단명 "발목 배측굴곡 제한", 설명 문단, 경고 박스(관절 부종/열감), "재활 루트 보기" 버튼까지 390px 폭에서 모두 카드 안에 정상적으로 줄바꿈되어 표시. 가로 스크롤 없음.
9. 재활 루트 화면("런지 무릎 · 가동성 부족"): 상단 탭 4개(1 기초재활/2 회복테스트/3 재평가/4 운동복귀)가 좁은 폭에서도 겹치거나 잘리지 않고 한 줄에 배치됨. 첫 운동 "월 앵클 모빌리티" 카드에서 "영상" 버튼, 방법 1~4단계, 큐잉 문구(보라색 박스), "왜 이 운동인가" 토글까지 확인. 토글을 펼치자 이유 설명 텍스트("족관절 전방 공간을... 기반을 만듭니다")도 두 줄로 자연스럽게 줄바꿈되며 카드 밖으로 넘치지 않음.
10. "기록 저장에 실패했습니다" 토스트 노출 — 기존에 확인된 데모 환경 특성(정상).

## 발견된 문제
발견된 문제 없음. 390×844(아이폰 15 기준) 폭에서 텍스트 잘림, 버튼 밖으로 나감, 요소 겹침, 가로 스크롤 등은 관찰되지 않음.

## 최종 결과
- 도달한 화면/판정: cause 판정 "런지 무릎 · 가동성 부족(발목 배측굴곡 제한)" → 기초재활 1단계(월 앵클 모빌리티, 밴드 거골 후방 견인 스트레칭 등) 진입 완료. danger 화면으로 전환되지는 않았음(경고 문구만 카드 내 참고용으로 노출).
- 390×844 화면에서 전반적인 사용성 평가: 좁은 폭에서도 카드/버튼/탭이 모두 자연스럽게 줄바꿈·배치되어 레이아웃 문제 없이 원활하게 사용 가능.

## 참고: 뷰포트 재현 방법 (도구 한계 기록)
`mcp__claude-in-chrome__resize_window`를 390×844로 호출하면 "성공" 응답은 돌아오지만, 실제로는 브라우저 창이 리사이즈되지 않고 화면 전체 크기(약 1536×912, 이 환경의 OS 해상도)로 유지됨 — `window.innerWidth` 등으로 재확인해 수치로 검증함(800×600 등 더 작은 값으로도 재시도했으나 동일하게 무효). 대안으로, 페이지 내부에 390×844 크기의 `<iframe src="http://localhost:8960/index.html">`를 주입해 그 안에서 앱을 다시 로드(같은 오리진이라 로그인 상태·앱 데이터는 localStorage로 공유되어 재로그인 불필요)하고, iframe 안에서 전체 플로우를 진행하며 스크린샷으로 실제 390px 폭 레이아웃(미디어 쿼리 포함)을 확인함. 이 방법으로 실제 아이폰 15 폭 기준의 신뢰할 수 있는 레이아웃 검증을 완료함.
