# 페르소나 테스트 통합 요약

8개 페르소나(동작별 1인) 시뮬레이션 테스트 결과 취합. 오판정으로 정정된 항목(페르소나8 "운동 콘텐츠 교차오염")은 실제 문제로 집계하지 않음.

## 핵심 발견: 위험신호 검증 결과

| 동작×부위 | 페르소나 | 위험신호 유형 | 질문 형태 | danger 화면 노출 |
|---|---|---|---|---|
| 풀업×어깨 | 4 | Drop Arm(회전근개 파열 의심) | 정적 텍스트뿐, 클릭 불가(onclick 없음) | **아니오** |
| 로우×허리 | 6 | 다리 저림/방사통(마미증후군 포함) | 정적 텍스트뿐, 클릭 불가(`dangerSignItem()`에 onclick 없음) | **아니오** |
| 키핑×손목 | 5 | 안정 시 저림 지속 | 인터랙티브 3지선다("쉬는 중에도") | **예**, 정상 |
| 스쿼트×허리 | (P6 코드조사로 확인) | 다리 저림/방사통 | 인터랙티브 질문 존재("다리로 저림·찌릿함이 내려가나요?") | 예, 정상(전체 파일 중 유일한 인터랙티브 저림 질문) |
| 데드리프트×무릎(외측) | 3 | 밸거스 정렬 회귀 검증 | 인터랙티브 정렬 테스트 정상 | 해당없음(정상 cause 분기 확인) |
| 수평 프레스×흉근 | 8 | 부종/열감/뚝소리 | 정적 텍스트, 병원권유거부감 페르소나가 무시하고 진행(의도된 정보제공형 설계) | 해당없음(정보 제공형, 강제 차단 아님) |

**결론**: "위험 신호는 즉시 멈춤"(핵심 원칙 5)은 스쿼트×허리, 키핑×손목 등 일부 동작에만 개별적으로 인터랙티브 질문이 구현되어 있고, 풀업×어깨·로우×허리에서는 `EXTRA_DANGER_SIGNS`가 `cause()` 화면에 정적 텍스트(`dangerSignItem()`, onclick 없음)로만 노출되어 실제 분기 로직에 연결되지 않음. 동일 구조적 버그가 최소 2개 동작×부위 조합에서 재현되어, 부위별 위험신호가 개별 동작 데이터에 인터랙티브 질문으로 추가되지 않은 경우 전반적으로 이 원칙이 지켜지지 않을 가능성이 높음.

## 발견된 문제 (심각도순)

| 심각도 | 동작 | 문제 | 위치 |
|---|---|---|---|
| 안전 | 풀업×어깨 (P4) | Drop Arm 위험신호를 사용자가 응답할 인터랙티브 질문이 없음. 정적 경고 텍스트만 노출, danger 화면으로 미연결 | 원인 확정 화면(82%) |
| 안전 | 로우×허리 (P6) | 다리 저림/방사통 위험신호를 응답할 인터랙티브 질문이 없음(동일 구조 버그, 스쿼트×허리는 예외적으로 정상) | `cause()` 화면, `EXTRA_DANGER_SIGNS['lower-back']` |
| 데이터 | 손목×키핑 (P5) | 저림 위험신호 감별이 "통증이 언제 느껴지나요" 단일 3지선다에만 의존, 저림을 직접 묻는 문항 없음 → 과민 분기(false positive) 가능성 | 챕터1 감별 질문 |
| 데이터 | 수직 프레스×고관절 (P7) | 고관절+수직프레스 조합 데이터 부재(고관절 선택 시 동작 옵션이 스쿼트·런지·데드리프트뿐) | 동작 선택 화면 |
| 데이터 | 스쿼트×무릎 (P1) | 무릎 앞/옆/뒤 위치를 세분화하는 질문이 없어, "무릎 앞쪽 통증" 전제와 최종 진단(대둔근·내전근 활성 저하=정렬 문제) 간 인과 설명이 약함(기존 "감별 분기 얕음 패턴"과 동일 계열) | 감별 질문 흐름 |
| 데이터 | 데드리프트 (P3) | 재활 루트가 4단계(기초재활→회복테스트→재평가→운동복귀)로 표시되나 CLAUDE.md는 3단계로 기술 — 문서·구현 불일치(기능 버그 아님) | 재활 루트 화면 / CLAUDE.md |
| 데이터 | 수평 프레스×흉근 (P8) | 2개 질문만으로 즉시 cause-c(과사용)로 수렴하는 얕은 분기 구조 — 애매한 답변이 구조적 원인(cause-b/d)을 놓칠 위험 | 감별 질문 1·2 |
| 데이터/사용성 | 전반(P1,2,3,4,6,7,8) | "기록 저장에 실패했습니다" 토스트 반복 발생. 로컬 서버 환경(백엔드 미연결) 특성일 가능성 높으나, 운영 환경(Railway) 재현 여부 미확인. P8에서는 이로 인해 재활 홈 "진행 중" 카드가 갱신 안 되는 것까지 확인됨 | 원인 확정/재활 루트 화면, `saveRehabRecord()` |
| 사용성 | 전반(P3,7,8) | localStorage 단일 키(`rehab_progress`)로 인해 이전 세션 상태와 뒤섞임 — "지금 시작하기" 연타 시 통증부위 선택을 건너뛰고 이전 세션 화면으로 점프, 되돌아가려면 홈 아이콘 클릭 필요(별도 "새로 시작" 버튼 없음) | 재활 홈 "지금 시작하기" |
| 사용성 | 전반(P4,6,8) | 재활 홈 "재활 진행 중" 카드가 새 감별 완료 후에도 갱신 안 되고 기존 무관 데이터("스쿼트·무릎")만 표시 | 재활 홈 화면 |
| 사용성 | 전반(P2,4,6,7,8) | "데모로 시작" 링크가 소셜 로그인 버튼(카카오/네이버/구글) 대비 작고 하단에 위치해 IT미숙 사용자가 찾기 어려움 | 로그인 화면 |
| 사용성 | 전반(P2,5,6,7,8) | 로그인 직후 첫 화면이 재활과 무관한 "기록"(러닝/캘린더) 탭 — 목적 화면("재활" 탭)으로 한 번 더 이동 필요 | 로그인 직후 |
| 사용성 | 전반(P1,2,5) | 재활 홈에서 "지금 시작하기"(신규)와 "이어하기"(기존 진행)의 구분이 직관적이지 않음 | 재활 홈 카드 |
| 사용성 | 데드리프트 (P3) | 통증부위 선택(10%) 직후 진행률이 30%로 점프(중간 단계 스킵 여부 불명확) | 진행률 바 |

## 다음 액션 제안

1. **[최우선/안전] 풀업×어깨(Drop Arm), 로우×허리(저림/방사통) 위험신호를 인터랙티브 질문으로 전환.** `EXTRA_DANGER_SIGNS`+`dangerSignItem()` 정적 텍스트 패턴에 의존하는 다른 부위×동작 조합 전체를 전수 조사(grep으로 "저림", "뚝 떨어져요" 등 키워드 검색해 인터랙티브 질문 존재 여부 대조)해 동일 버그가 몇 곳에 더 있는지 파악 후 일괄 수정.
2. **[안전] 손목×키핑의 저림 단일문항 의존 구조 재검토.** 저림 유무를 직접 묻는 문항을 추가해 과민 분기(false positive) 가능성을 낮출지 검토.
3. **[데이터] 고관절+수직프레스 조합 데이터 추가 여부 결정.** 없다면 통증부위-동작 선택 UI에서 애초에 불가능한 조합이 노출되지 않도록 처리.
4. **[사용성] localStorage 단일 키로 인한 세션 뒤섞임 수정.** "지금 시작하기"를 항상 새 세션으로 명확히 분리하거나, 진행 중 세션이 있을 때 확인 다이얼로그 추가.
5. **[사용성/데이터] "기록 저장에 실패했습니다" 토스트 원인 규명.** 실제 배포 환경(GitHub Pages+Railway)에서 재현되는지 확인, 재현 시 재시도 로직 또는 로컬 폴백 추가.
6. **[사용성] 로그인 후 첫 화면 및 "데모로 시작" 링크 시인성 개선.** 재활 목적 사용자를 위해 첫 화면을 "재활" 탭으로 바꾸거나, 온보딩 시 안내 고려.
7. **[데이터] 감별 분기 얕음 패턴(스쿼트×무릎 위치 미세분화, 수평 프레스 2문항 즉시 수렴) 전반 검토** — 기존 memory 이슈와 연계해 PT 검수 체크리스트에 포함.
8. **[문서] CLAUDE.md의 "3단계" 표기와 실제 구현 "4단계"(기초재활→회복테스트→재평가→운동복귀) 불일치 정리.**
