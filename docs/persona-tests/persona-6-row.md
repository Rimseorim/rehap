# 페르소나 6: 51세 여 · 로우

## 프로필
- IT숙련도: 미숙 / 증상설명정확도: 정확 / 증상민감도: 둔감 / 병원권유수용도: 거부감 / 크로스핏경력: 숙련
- 시나리오: 허리 통증 + 다리 저림/방사통(위험신호) — 2번째 안전 핵심 시나리오

## 진행 기록
1. 로그인 화면: "데모로 시작" 링크가 화면 하단에 작게(회색, 밑줄만) 표시되어 있어 IT미숙 페르소나 기준으로 카카오/네이버/구글 버튼에 먼저 시선이 가고, 실제 클릭까지 화면을 한 번 더 훑어야 했음 → 페르소나4와 동일한 관찰.
2. 로그인 직후: "기록" 탭(캘린더+러닝 기록)이 첫 화면으로 노출됨. 재활 감별과 무관한 화면이 먼저 보여 IT미숙 사용자는 목적 화면을 못 찾을 수 있음.
3. 하단 탭에서 "재활" 클릭 → 이동. 이미 진행 중인 세션 카드("스쿼트·무릎", 기초 재활 단계)가 있었음. "지금 시작하기" 버튼으로 새 감별 시작.
4. 통증 부위 화면(10%): "허리" 선택 → 정상 전환.
5. 동작 선택 화면(30%): "로우" 선택 → 정상 전환, breadcrumb "허리 > 로우" 노출.
6. 챕터1·감별 질문(30%): "통증이 언제 느껴지나요?" — 선택지 "당기는 동작 중" / "앞으로 숙인 자세를 유지할 때" / "쉬는 중에도 욱신거린다"(→danger). **여기서 다리 저림/방사통 관련 질문이 아예 등장하지 않음.** "당기는 동작 중" 선택.
7. 챕터1·감별 질문(43%): "로우 자세에서 허리가 둥글게 말리는 편인가요?" — 이 질문 역시 저림과 무관. "네, 등이 둥글어져요" 선택.
8. 챕터2·직접 테스트(56%): "버드독 로터리스태빌리티 검사" — 4단계 방법 안내 + 영상 링크 정상 노출. 결과 선택지 중 "뻗을 때 허리가 처지거나 골반이 돌아가요" 선택.
9. 원인 확정 화면(82%): "요추 굴곡 과부하 (라운드 백)" 진단, 설명 정상. 하단에 danger-box(빨간 배경)로 3개 항목 노출:
   - "관절이 눈에 띄게 부어있어요"
   - "만지면 열감이 느껴져요"
   - "양쪽 다리에 동시에 저림이나 힘빠짐이 있어요" (sub: "사타구니·엉덩이 안쪽 감각이 둔하거나 대소변 조절이 갑자기 안 되는 경우 포함")
   세 항목 모두 클릭해봤으나 **어떤 반응도 없음**(포인터 커서 변화도 없고 danger 화면으로 전환도 안 됨) → 정적 텍스트로 확인.
   - 화면 하단에 "기록 저장에 실패했습니다"라는 어두운 버튼형 알림도 노출됨(클릭 후 사라짐). 로컬 데모 환경(백엔드 미연결) 특성으로 보이나 실제 배포 환경에서도 나타나면 데이터 손실 우려.
10. "재활 루트 보기" 클릭 → 재활 루트 화면(82%) 진입. 헤더 "로우 허리 · 기술 오류", "요추 굴곡 과부하 (라운드 백)" 서브타이틀, 단계 탭(1 기초재활/2 회복테스트/3 재평가/4 운동복귀) 정상 노출. "캣-카멜" 운동 카드에 "왜 이 운동인가" 토글이 정상 작동(척추 분절 이완 설명 노출) — 핵심 원칙 "이유를 붙인다" 충족 확인.

## 안전 검증 결과
- 저림/방사통 위험신호 질문 형태(인터랙티브 vs 정적 텍스트): **정적 텍스트뿐**. 로우×허리 감별 흐름(entry q1 → q2 → test-row-rotary-stability → cause)에는 다리 저림/방사통을 묻는 인터랙티브 질문 노드가 전혀 존재하지 않음. 유일하게 존재하는 관련 항목은 `cause()` 화면에 `EXTRA_DANGER_SIGNS['lower-back']`으로 하드코딩된 경고 박스 텍스트("양쪽 다리에 동시에 저림이나 힘빠짐이 있어요")이며, 이는 `dangerSignItem()`으로 렌더링되는 순수 정보 카드로 onclick이 없어 클릭해도 아무 반응이 없음.
- danger 화면 노출 여부: **아니오**. 원인 확정 화면까지 도달했고, 위험신호 텍스트를 클릭해도 danger 화면으로 전환되지 않음.
- danger 화면 문구 원문: 해당 없음(화면이 뜨지 않았으므로 인용 불가). 대신 노출된 정적 경고 문구는 다음과 같음: "양쪽 다리에 동시에 저림이나 힘빠짐이 있어요 / 사타구니·엉덩이 안쪽 감각이 둔하거나 대소변 조절이 갑자기 안 되는 경우 포함 / 위 항목에 해당된다면 재활 전 전문의 진단을 먼저 받으세요."
- 코드 근거(index.html):
  - `EXTRA_DANGER_SIGNS['lower-back']` (1504~1507행): `title: '양쪽 다리에 동시에 저림이나 힘빠짐이 있어요'`. `cause()` 함수(1529~1548행)에서 `dangerSignItem(extraSign.title, extraSign.sub)`로 렌더링되며 onclick 핸들러 없음(1518~1527행 `dangerSignItem()` 정의에 클릭 로직 없음, 순수 마크업 반환).
  - 로우 동작의 lower-back painSite 노드(BUNDLED 데이터, index.html 4행 내부, "로우" 블록 offset 약 730973): `entry_question:"q1"` → q1 "통증이 언제 느껴지나요?"(선택지에 저림 언급 없음) → q2 "로우 자세에서 허리가 둥글게 말리는 편인가요?"(저림과 무관) → `test-row-rotary-stability` → `cause-a`/`cause-b`/`cause-c`. **저림/방사통을 묻는 인터랙티브 질문("다리로 저림·찌릿함이 내려가나요?", `next:"danger"`)은 이 파일에 정확히 1곳만 존재하며(전체 파일에서 "다리로 저림·찌릿함이 내려가나요?" 검색 시 1건), 그 위치는 스쿼트×허리(lower-back) painSite 노드(offset 약 28736) 안이다.** 즉 같은 통증부위(허리)라도 동작이 "스쿼트"냐 "로우"냐에 따라 저림 스크리닝 질문의 존재 여부가 다르며, 로우 쪽에는 아예 빠져있음.
  - 페르소나4(풀업×어깨)에서 확인된 "Drop Arm 위험신호가 정적 텍스트로만 존재" 패턴과 **동일한 구조적 문제**: `EXTRA_DANGER_SIGNS`는 부위(painSiteId)별로 한 세트만 정의돼 있고, `cause()` 화면에서만 한 번 정적으로 노출될 뿐 어떤 동작(movement)의 감별 질문 트리에도 자동으로 연결되지 않는다. 스쿼트처럼 데이터 작성자가 개별적으로 인터랙티브 질문을 추가한 동작만 정상 작동하고, 로우처럼 추가하지 않은 동작은 완전히 정적 텍스트에만 의존한다.

## 발견된 문제
- [심각도: 안전] 로우×허리 감별 흐름에 다리 저림/방사통(마미증후군 의심 등 응급 신호 포함)을 실제로 감지하는 인터랙티브 질문이 없음. 사용자가 시나리오대로 "다리까지 저림이 내려간다"는 위험 증상을 가지고 있어도, 이를 입력할 화면 자체가 없어 앱은 그냥 일반 재활 루트(요추 굴곡 과부하)를 배정한다. 경고 문구는 원인 확정 화면 하단에 텍스트로만 노출되고 클릭해도 아무 반응이 없어, "위험 신호는 즉시 멈춘다"는 핵심 원칙이 로우 동작에서는 실질적으로 지켜지지 않음. — cause() 화면(EXTRA_DANGER_SIGNS['lower-back']) / 로우×허리 painSite 데이터
- [심각도: 사용성] 원인 확정 화면에서 "기록 저장에 실패했습니다"라는 알림이 노출됨. 백엔드 미연결(로컬 데모) 환경 특성일 가능성이 높지만, 실제 배포 환경에서도 발생 시 사용자가 감별 결과를 잃을 수 있어 확인이 필요함. — 원인 확정 화면 하단
- [심각도: 사용성] 로그인 후 첫 화면이 "기록"(러닝 캘린더) 탭이라, 재활 감별이 목적인 사용자가 "재활" 탭을 직접 찾아 눌러야 함. IT미숙 페르소나에게는 진입 장벽. — 로그인 직후 화면 (페르소나4와 동일 관찰 반복 확인)
- 참고(버그 아님): 원인 확정/재활 루트 화면 제목에 "기술 오류"라는 문구가 노출되는데, 이는 렌더링 오류가 아니라 데이터상 실제 태그값(`"tag":"기술 오류"`, cause-a 정의)임을 확인함. 태그 표시 자체는 CLAUDE.md 원칙("태그+진단명 표시")과 부합.

## 최종 결과
- 배정된 결과: danger 안내 없이 cause "요추 굴곡 과부하 (라운드 백)" 및 4단계 재활 루트(기초재활→회복테스트→재평가→운동복귀) 배정.
- 시나리오 의도와 일치 여부: **불일치**. 시나리오는 다리 저림/방사통을 "예/해당됨"으로 답변해 danger 경로로 빠지는 것을 검증하려 했으나, 답변할 인터랙티브 질문 자체가 로우×허리 흐름에 존재하지 않아 danger 화면에 도달할 방법이 없었음. 페르소나4(풀업×어깨 Drop Arm)에서 발견된 "위험신호가 정적 텍스트로만 존재" 버그가 허리×로우 조합에서도 동일하게 재현됨을 확인 — 두 사례를 종합하면 `EXTRA_DANGER_SIGNS`에 의존하는 부위 전반에서 구조적으로 같은 문제가 있을 가능성이 높음(스쿼트×허리처럼 개별적으로 인터랙티브 질문을 추가한 소수 동작만 예외).
