# 페르소나 2: 24세 여 · 런지

## 프로필
- IT숙련도: 미숙 / 증상설명정확도: 정확 / 증상민감도: 둔감 / 병원권유수용도: 거부감 / 크로스핏경력: 초보
- 시나리오: 무릎 경미한 통증, 위험신호 아님(거부감 답변이 오분류로 이어지는지 검증)

## 진행 기록
1. 로그인 화면: 카카오/네이버/구글 로그인 버튼 3개가 크고 눈에 띔. 실제 진입 경로인 "데모로 시작"은 화면 맨 아래 작은 텍스트 링크 → 행동은 의도대로(클릭 성공) 됐지만, IT미숙 사용자라면 큰 버튼들 사이에서 작은 텍스트 링크를 놓치고 소셜 로그인부터 시도할 가능성이 있음.
2. 데모 로그인 직후: "기록" 탭(러닝/크로스핏 캘린더)이 첫 화면으로 표시됨. 통증 재활과 무관한 기존 기록(러닝 5.2km 등)이 보여, "통증 원인을 알아보러 왔는데 이게 뭐지" 하고 잠깐 헤맬 수 있는 지점. 하단 네비게이션에서 "재활" 탭을 찾아 이동해야 함 — 아이콘(달리는 사람 모양)만으로는 "재활" 의미가 바로 안 와서 라벨 텍스트를 같이 봐야 확인 가능했음.
3. 재활 탭: 이미 진행 중인 "스쿼트·무릎" 재활 카드가 있고 "지금 시작하기"/"이어하기" 버튼이 나란히 있음. 새 통증(런지)을 감별하려면 "지금 시작하기"를 눌러야 하는데, "이어하기"와 문구가 비슷해 신규 통증 감별 진입점이라는 게 직관적이지 않음.
4. 통증부위 선택: "무릎" 클릭 → 정상 진행. 선택지 문구 명확, 문제 없음.
5. 동작 선택: "런지" 클릭 → 정상 진행. breadcrumb(무릎 › 런지)이 상단에 표시되어 진행 상황 파악에 도움됨.
6. 감별 질문(통증이 언제 느껴지나요): "어느 정도 반복한 후" 선택(경미·과부하성 반영) → 정상 진행.
7. 무릎 위치 질문: "앞쪽(슬개골 주변)" 선택 → 정상 진행. 괄호 안 해부학 용어(슬개골)가 있어 IT/의학 지식 없는 사용자는 곧바로 이해하기 어려울 수 있으나, 큰 걸림돌은 아니었음.
8. 직접 테스트 1 (발목 배측굴곡 테스트): 텍스트 설명 3단계 + "영상으로 보기" 버튼 제공. "무릎이 벽에 닿아요"(정상) 선택. IT미숙+실기 테스트 특성상, 스스로 정확히 수행했는지 자신 없는 상태로 결과를 골라야 했음 — 영상 안내가 있어 다행이나, 클릭해서 재생을 확인해보진 않음(영상 버튼 자체 동작은 미검증).
9. 직접 테스트 2 (런지 무릎 정렬 테스트): "무릎이 발끝 방향 유지"(정상) 선택 → 정상 진행.
10. 직접 테스트 3 (디클라인 스텝다운 — 슬개대퇴 압박 통증 확인): 이 질문은 시나리오상 핵심 증상 확인 질문(부가 질문 아님)이라 실제 증상을 정확히 반영 — "굽히는 동안 무릎 앞쪽(슬개건)에 통증이 있어요" 선택.
11. 원인 확정 화면: "슬개대퇴 증후군(대퇴사두근 과부하)" 판정, 태그 "과부하" 표시. 설명 문구("대퇴사두근이 런지 부하를 감당하기엔 아직 약하거나 갑자기 볼륨이 늘어난 것이 원인")가 이해하기 쉬웠음. 화면 하단에 위험신호 체크리스트("관절이 눈에 띄게 부어있어요", "만지면 열감이 느껴져요")가 안내 문구로만 표시되고, 별도의 클릭형 응답(예/아니오) 없이 자동으로 "재활 루트 보기"로 넘어감.
12. **관찰된 버그**: 이 화면 하단에 "기록 저장에 실패했습니다"라는 에러 토스트가 표시됨(스크린샷 확인). 사용자 입력에는 영향 없이 다음 단계로 진행은 가능했으나, 저장 실패 자체가 문제.
13. 재활 루트 화면: "런지 무릎·과부하 / 슬개대퇴 증후군(대퇴사두근 과부하)", 4단계 탭(기초재활/회복테스트/재평가/운동복귀) 정상 표시, "진행 단계 1/4". 첫 운동(햄스트링 스트레칭) 카드에서 "왜 이 운동인가" 토글 클릭 → "햄스트링을 이완합니다. 햄스트링 긴장이 슬개골에 간접적 부담을 줄 수 있습니다" 설명 정상 노출. 동작 단계별 안내(1·2·3)와 주의사항 문구도 명확.

## 발견된 문제
- [심각도: 데이터] 원인 확정 화면에서 "기록 저장에 실패했습니다" 에러 토스트 발생 — 원인 판정 결과가 실제로 사용자 기록(캘린더 등)에 저장됐는지 불확실. 재현 조건 및 저장 실패 원인 확인 필요 — 화면: 원인 확정 단계(무릎›런지, "원인을 찾았습니다").
- [심각도: 안전] 위험신호 체크리스트("관절이 부어있어요", "만지면 열감이 느껴져요")가 원인 확정 화면에 정보성 문구로만 표시되고, 사용자가 명시적으로 "예/아니오"를 클릭하는 구조가 아님. 둔감·거부감 성향 사용자는 실제로 해당 사항이 있어도 그냥 읽고 넘길 수 있어, 핵심 원칙 5("위험 신호는 즉시 멈춤")가 이 지점에서는 사용자 응답 없이 문구 노출에만 의존하는 구조로 보임 — 화면: 원인 확정 단계 하단 경고 박스.
- [심각도: 사용성] 데모 로그인 직후 첫 화면이 재활과 무관한 "기록"(러닝/크로스핏 캘린더) 탭이라 목적지(재활 감별)를 찾아 하단 탭으로 한 번 더 이동해야 함 — IT미숙 사용자는 첫 화면에서 잠깐 헤맬 수 있음.
- [심각도: 사용성] "데모로 시작" 진입 링크가 소셜 로그인 버튼 3개에 비해 매우 작고 하단에 위치 — IT미숙 사용자가 놓치기 쉬운 위치.
- [심각도: 사용성] 재활 탭에서 기존 진행 중 재활("스쿼트·무릎")과 신규 감별 시작("지금 시작하기")이 한 화면에 같이 있어, 새 통증 부위를 감별하려는 사용자가 "이어하기"와 혼동할 여지가 있음.

## 최종 결과
- 배정된 cause/루트: 런지 · 무릎 · 과부하 태그 → 슬개대퇴 증후군(대퇴사두근 과부하) → 기초재활 1단계(진행 단계 1/4) 진입
- 시나리오 의도와 일치 여부: **일치**. "경미한 무릎 통증, 위험신호 아님" 시나리오대로 danger 화면 없이 정상적으로 원인 판정→재활 루트까지 도달했고, 거부감 성향 답변으로 인한 오분류(위험 신호 경로로 잘못 빠지거나, 반대로 실제 위험을 놓치는 등)는 관찰되지 않음. 다만 위험신호 체크 항목이 클릭형 응답이 아니라 정보 문구로만 제공되는 구조는 향후 실제 위험신호 사용자에게는 리스크가 될 수 있어 별도 검토 권장.
