### task #1 — 발목 원인 3분류 반영 (설계 확정, 구현 전)

**배경**: SFMA 한발서기 캐스케이드(균형감각→코어안정성→발목가동성) 참고. 지금 앱은 발목 "불안정" 원인을 전부 구조적 인대 문제로만 취급 중 — 균형감각/코어조절력 문제로 발목이 흔들리는 케이스가 감별 안 됨.

**BUNDLED 데이터 확인 결과** (index.html 내 `BUNDLED=` 객체, JSON 형태):
- 스쿼트 발목: `cause-a`(관절충돌) `cause-b`(과부하) `cause-c`(불안정=만성외측발목불안정) `cause-d`(컨디셔닝부족)
  - `q2`에서 "바깥쪽·접질렸던 부위" 선택 → `test:test-ba-balance`(한발균형테스트: 눈뜨고30초→눈감고15초) → pass→`cause-d`, fail→`cause-c`
- 런지 발목: `cause-a`/`cause-a-mild`(가동성부족) `cause-b`(불안정성=외측인대불안정성) `cause-c`(과부하)
  - `q2`에서 "바깥쪽 또는 복숭아뼈" 선택 → **테스트 없이 즉시** `cause:cause-b` 직행 (스쿼트와 구조 다름)
  - 런지의 `test-ankle-stability-retest`는 초기진단용이 아니라 재활 진행 중 회복테스트(retest)용 별도 노드 — 혼동 주의
- 데드리프트: 발목 통증부위 자체가 없음(해당 없음)

**확정된 설계안** (사용자 승인 완료, Phase A/B 콘텐츠 설계는 아직):
1. 신규 후속 질문(스쿼트는 `test-ba-balance` **fail 분기 후**, 런지는 `q2` "바깥쪽" 선택 **직후**에 삽입):
   > "흔들릴 때 발목만 꺾이는 느낌인가요, 무릎이나 골반까지 같이 흔들리나요?"
   - "발목만" → 기존 cause 유지 (스쿼트 `cause-c`, 런지 `cause-b`, 변경 없음)
   - "무릎·골반도 같이" → **신규 원인**으로 라우팅
2. 신규 원인 스펙 (스쿼트 `cause-e`, 런지 `cause-d` — id는 기존 마지막 알파벳 다음으로):
   - tag: "조절력 부족"
   - name: "고관절·코어 조절력 저하로 인한 발목 불안정"
   - description: "발목 자체 인대 문제가 아니라, 한 발로 체중을 지탱할 때 고관절·코어가 골반을 못 잡아줘서 그 흔들림이 발목까지 전달되는 경우입니다. 발목만 강화해도 잘 해결되지 않습니다."
   - priority_note: "발목 강화보다 고관절·코어 조절력 회복이 먼저입니다."
3. 질문 증가량: 균형테스트 **통과자(대부분)는 추가 질문 0개**, **실패자만 후속 질문 1개** 추가 — 전체 사용자 기준 체감 복잡도 증가 미미하다고 판단, 사용자 확인 완료.
