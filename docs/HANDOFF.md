## 결정사항 / 주의
- 페르소나 테스트는 반드시 **자율 방식**으로: 프로필(성격+백스토리)만 주고 통증부위·동작·질문 답변은 페르소나가 스스로 판단하게 할 것. 코디네이터가 답을 스크립트로 지정하면 안 됨 (1차 시도가 이 원칙 위반으로 전량 폐기됨)
- 다음 페르소나 테스트 시 휴대폰 기종(아이폰/갤럭시, 화면크기)도 프로필에 포함할 것 — 이번엔 뒤늦게 추가함
- claude-in-chrome의 `resize_window`는 이 환경에서 실제로 작동 안 함(성공 응답은 오지만 no-op) — 뷰포트 테스트 필요 시 `<iframe style="width:...;height:...">` 주입 방식으로 우회
- "기록 저장에 실패했습니다" 토스트, 선택지 파란 테두리 사전강조는 둘 다 정상 동작(데모 백엔드 미연결 / 브라우저자동화 hover 잔상, 앱은 휴대폰 전용이라 실사용자 무관) — 재조사 불필요
- cause 설명 텍스트에서 "구체적 동작명 vs 일반화" 판단 기준: 원인을 특정 동작에 **직접 귀속**시키는 문장(예: "OO 동작에서 아프면 이게 원인")은 동작명이 틀리면 실제 오류이므로 동작명 수정 필요. 원인의 **역학적 배경**을 설명하는 문장(예: "OO에서 흔합니다")은 참고정보라 다른 동작에서 봐도 틀린 말이 아님 — 무조건 일반화하지 말고 이 기준으로 판단
- index.html은 단일 거대 minified 라인(BUNDLED JSON)이라 동일 문자열이 여러 동작에 중복될 때 Edit 도구로 구분 불가 — Node 스크립트로 바이트 오프셋 기준 위치 판별 후 드라이런(콘솔 출력으로 매핑 확인) → 실제 적용 → JSON 유효성 검증 순서로 진행 (Write 도구는 스크립트 파일 생성에만 사용, index.html 자체는 스크립트가 fs.writeFileSync로 직접 갱신)
