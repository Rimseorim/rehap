# 영상 검수 규칙

영상 검수판(Artifact)과 함께 전달하는 규칙 문서. 검수 이어받는 사람은 이 기준으로 판단할 것.

## 수정 범위 규칙

- **사실관계·해부학적 오류** (동작 방향, video_url 오배정 등) → 같은 id를 쓰는 **모든 중복 인스턴스**에 동일 적용
- **문구·스타일 수정** (표현 방식, 각도→패턴 언어 전환 등) → **검토 중인 그 인스턴스에만** 적용, 다른 동작의 중복 인스턴스는 안 건드림

## "검수 완료" 기준

- 제목/영상 링크만 확인하고 완료 표시 금지
- steps·note·passText·failText 본문까지 실제로 다 확인했을 때만 완료

## 영상 신뢰성 검증

- 영상 내용만 보고 판단하지 않는다 — 순서·방법이 의심되면 임상 자료(WebSearch로 Physiopedia, Orthofixar 등 근거 자료)로 교차 검증 후 수정
- video_url이 여러 다른 이름의 테스트에 동일하게 붙어 있으면 복붙 오류 의심 신호 — 전수 grep으로 재사용 현황 확인

## 용어 규칙 (본문)

- 사용자 노출 필드(name/purpose/note/why/steps)의 의학 전문용어는 쉬운 말 + 괄호 안 원어 병기
  - 예: 장요근 → "고관절 앞쪽 근육(장요근)", 고관절 외전근/중둔근 → "엉덩이 옆 근육(중둔근)"
- "엉덩이"는 둔근(뒤쪽) 어감이 강해 몸 앞쪽 부위 설명엔 쓰지 않는다
- `target_area` 등 화면에 렌더링되지 않는 내부 메타데이터 필드는 치환 대상에서 제외 (렌더링 여부는 코드에서 `.필드명` 접근 확인)

## 영상 링크 규칙

- 기준은 영상 전체 길이가 아니라 **"검사 동작이 실제로 나오는 시점이 앞부분에서 얼마나 떨어져 있는가"**다
- 검사 동작이 시작되기까지 인트로·무관한 설명이 길게 낀다면(대략 15~20초 이상) 그 지점으로 **타임스탬프(`&t=초`)를 붙여서** 링크한다
  - 예: `...&t=45`, `...&t=145`
- 동작이 영상 앞부분(10초 안팎)에 바로 나오면 영상이 1분을 넘더라도 타임스탬프 불필요
- 반드시 실제로 재생해서 동작이 나오는 지점을 확인한 뒤 붙인다 — 길이만 보고 추정하지 않는다

## 용어 규칙 — 범위 경계 (중요: 지금 확대하지 말 것)

영상 검수 중 발견했지만 **지금 범위에 넣지 않고 "글귀 전체 검토"(사용자가 별도로 진행 예정)로 넘긴 것들**. 나중에 그 작업을 할 때 아래 기준으로 판단할 것.

- 판단 기준 3가지: (1) 사용자 노출 필드에 있는가 (`target_area`처럼 렌더링 안 되는 필드는 제외), (2) 이미 쉬운말이 붙어 있는가(예: "무릎 앞쪽(슬개건)"은 이미 통과, 안 붙어있으면 대상), (3) 일반인이 위치·역할을 짐작 못 하는 이름인가 (관절·부위 자체 이름인 무릎·어깨·허리 등은 제외)
- 이 기준으로 걸리는 것들이 이미 수백~수천 건 단위라 영상 검수(테스트 하나씩) 범위를 훨씬 벗어남 — 발견 시점에 등장 횟수(사용자 노출 필드 기준, 대략치):
  - 관절낭 341 / 승모근 332 / 전거근 286 / 대퇴사두근 184 / 회전근개 162 / 능형근 140 / 이두건 102 / 이상근 63 / 좌골결절 11
  - 움직임 방향 용어(관절 동작 설명 전반에 깔려 있음): 회전 904 / 굴곡 851 / 신전 846 / 굴곡근 532 / 신전근 366 / 내전 82 / 외전 39
- 위 숫자는 텍스트 전체를 사실상 다시 쓰는 규모라, 영상 검수에서 발견해도 그 자리에서 고치지 않고 이 목록에만 기록해 둔다

## 테스트명(제목) 규칙

- 형식: **"[원어] 검사 — [쉬운 설명]"** — 고유명사(인명)나 약어를 맨 앞에 그대로 쓰고, 대시 뒤에 이해하기 쉬운 설명을 붙인다. 괄호를 추가로 쓰라는 뜻이 아니라 이 순서·구분자로 통일하라는 뜻
  - 예: "FADIR 검사 — 고관절 앞쪽 충돌 확인", "토마스 검사 — 고관절 앞쪽 근육 긴장 확인"
  - 여기서 "원어"란 FADIR·TFCC·ASLR 같은 약어, 토마스·코젠 같은 인명(고유명사)을 가리킴 — 그 자체로는 뭘 확인하는 검사인지 알 수 없는 이름
- 구분자는 대시(`—`)로 통일 — 괄호 `()`로 설명을 붙이던 기존 표기도 대시로 정리
- 이 형식을 고른 이유: "쉬운 설명이 맨 앞에 오게" 방식은 검사마다 자연스러운 설명 문구를 새로 지어야 해서 품질 편차가 크고 나중에 일괄 처리가 어려움. 반면 "원어 + 대시 + 설명"은 기계적으로 일관 적용 가능하고, FADIR·토마스·코젠 같은 용어는 PT나 이미 아는 사용자에게 빠른 인식 키워드로도 쓰인다
- 주의: 한글로 표기했다고 쉬운 말이 되는 게 아니다 — "토마스 테스트"는 한글이어도 인명이라 그 자체로는 뭘 확인하는지 알 수 없음. 판단 기준은 언어가 아니라 "맨 앞 단어가 뭘 하는 검사인지 설명하는가"
- 인명·고유명사는 **영문이 아닌 한글 표기(토마스, 코젠 등)로 통일** — 영어로 적어도 이해도는 올라가지 않고(어차피 이름이라 뜻을 알 수 없음), 나머지 한국어 문장과 어울리지 않음. 검색·인지 목적은 한글 표기로도 충분

## 반영 대상 (양쪽 동기화 필수)

- `index.html` (BUNDLED 데이터, 실제 서비스)
- 검수판 Artifact (수동 미러 — 매번 최신 버전 read → 전체 확인 → edit → publish)
